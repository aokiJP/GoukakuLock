# 合格ロック 仕様書(完全版 / v3)

本書は合格ロックの全体仕様を 1 本にまとめたもの。これだけ読めば、思想・安全の床・ロック・コミット・相棒 AI・預け金・配布・技術構成が分かる。
実装を進めるときの作業指示は `docs/v3-build-prompt.md`(こちらは「何を変えるか」の短い版)を併用する。

- アプリ: 合格ロック(iOS / SwiftUI、ipa 配布想定)
- いまの版: v2.1.1 (6) → 本書は **v3**(AI 前提の UX・一文で即解除・配布整理・AI 機能追加)
- 言語: 日本語(コード・画面・ドキュメントすべて)

---

## 1. これは何か

本人が自分で決めた目標・習慣を「やった」と確かめるまで、決済・買い物・SNS などのアプリを iOS の Screen Time（FamilyControls / DeviceActivity / ManagedSettings）でロックする、習慣化・自己管理アプリ。

- **アプリは試験を作らない・採点しない。** 何を達成とするかは本人が決め、本人が確かめる
- 相棒 AI は端末内で動く伴走者。義務ではなく人生の体験を勧める
- データは端末内で完結。外に出るのは、本人が選んだ預け金の最小データ（日付とその日の結果）だけ
- 本人はいつでも逃げられる（安全の床）

---

## 2. 思想と原則

1. **自分で決める / 自分で確かめる。** 外から課す試験ではない
2. **閉じ込めないまま、本気にさせる。** 逃げ道は常に開く。強制力は「閉じ込め」ではなく「身銭（自己コミットの預け金）」に置く
3. **ゆるめる変更は翌日から。** 今日の条件は途中で甘くしない（厳しくするのは即時 or 翌日）
4. **相棒は裁かない。** 下書き・提案・伴走に徹し、合否や解除可否を決めない
5. **端末内・無検閲。** 会話もデータも端末に留め、端末内 AI に内容フィルタを足さない
6. **お金は自己コミット。** 本人の金を預け、戻るのも本人の口座。他人には渡さない

---

## 3. 安全の床（最重要・不変条件）

どんな状態・どんな UX でも、次は必ず生きている。ここに反する実装はしない。

- **やめる（即解除）はいつでもできる。** v3 では一文で即、ロックを外す（§10.3）
- **緊急解除**: 申請から **15 分待機**、その後 **120 分**解除。この 2 つの数値は安全の床で**変更不可**（`EmergencyPolicy.waitMinutes=15` / `windowMinutes=120`）。待機中・解除中は重ねて申請できない
- **一時停止**: ロック全体の非常口。停止中はロックがかからない。何より優先される
- **AI は解除を拒めない・遅らせない・値切らない。** 意図を汲んだら即実行。AI が止める経路を作らない
- **解除には AI 非依存の確実な道を常備。** 端末内 LLM が失敗しても解除できる決定的経路（合言葉の完全一致＋最後の最小操作）を残す
- **お金で閉じ込めない。** 預け金は自己コミット（本人の口座に戻る/残る）。途中でやめても他人は得をしない
- **時刻改ざんに強く、でも罰しない。** 壁時計と単調時計のずれを検知（`TamperDetector`、許容 120 秒）。判定の保護に使い、ユーザーを罰する方向には使わない

## 4. 用語

| 語 | 意味 |
|---|---|
| サイクル（CycleID） | 1 日の単位。日付切替時刻で区切る |
| 日付切替（dayStartMinute） | 0:00 からの分。既定 240=4:00。0〜360、30 分刻み |
| コミット（HabitSnapshot） | 本人が決めた習慣。必須/任意、最小版の有無、曜日、確認方法を持つ |
| 達成（Achievement） | チェックイン 1 回。full/minimum、確定/承認待ち 等 |
| 結果（CycleOutcome） | そのサイクルの判定。達成/最小/未達成/休養/予定なし/一時停止/進行中/開始前 |
| 見守り（monitorOnly） | ロックせず記録だけ続けるモード |
| 執行役（referee） | 緩める変更・承認を頼む相手（任意） |
| やめる合図 | 「檻に感じ始めたら、それがやめる合図」。本書 §10.3 |

## 5. 全体の流れ / 画面（v3: AI 前提の UX）

v3 は**会話を入口**にする。日常操作はできるだけ相棒との会話で完結させ、タップ前提を減らす。

- 入口: 「相棒と話す」。チェックイン・コミット作成/変更・ふり返り・預け金・やめる を自然文で
- 既存画面（ホーム / 体験 / 記録 / 設定）は、会話からの深掘り先として残す（全撤去はしない）
- **会話にしない＝ネイティブを残す**:
  - Screen Time の許可（FamilyControls 認可）、iOS の権限ダイアログ
  - 支払い画面（Stripe PaymentSheet / Apple Pay）
  - 解除の最後の保険（§10.3 の決定的経路）
  - アクセシビリティ/確実性のための最小フォールバック（VoiceOver、会話が使えない状況）
- 破壊的・お金が動く操作は、AI の判断だけで確定せず**短い確認**を挟む。ただし **やめる/一時停止は確認なしで即実行**

## 6. 時間の扱い

- サイクル = 日付切替から次の切替まで。既定 4:00 区切り（夜型の生活に合わせやすい）
- 日付切替の変更は**記録の意味が変わる**ため、**一時停止中にだけ**できる（§9）
- 夏時間・日付切替の変更に備え、預け金の「次の週の日の始まり」はアプリの暦で計算してサーバーに渡す（§12）

## 7. ロックの仕組み

### 7.1 ロックモード（LockMode）

- **朝からロック（morning）**: サイクル開始と同時にロック。その日の必須コミットを全部達成すると次サイクルまで解除
- **夕方からロック（evening(lockStartMinute)）**: その時刻までは猶予。達成していなければロック。前サイクルが未達成なら猶予なし（持ち越し）
- **稼働型（earn(windowMinutes)）**: 常にロック。達成 1 回ごとに windowMinutes だけ解除（`Achievement.grantsMinutes`）。自己申告だけでは不可（何度でも押せてしまうため、タイマー/写真/使用時間で確かめる）

### 7.2 実施レベル（Enforcement）

- **lock**: 実際にロックする
- **monitorOnly（見守り）**: ロックせず記録だけ続ける（慣らし・観察用）

### 7.3 Screen Time 実装

- FamilyControls で対象アプリ/カテゴリを選ぶ（`LockTargets`、上限あり）
- DeviceActivity でスケジュール/しきい値を監視、ManagedSettings でシールド
- 共有状態 `SharedState`（App Group の `state.json`）に判定材料を集約。**本体だけが書き、拡張・ウィジェットは読むだけ**。直近 14 サイクル分の達成を保持
- ロック中のオプション: アプリ内課金の抑止（`LockOptions.denyInAppPurchases`）

### 7.4 拡張

- `GoukakuMonitor`（DeviceActivityMonitor：使用時間の自動判定）
- `GoukakuShieldConfig` / `GoukakuShieldAction`（シールドの見た目・操作）
- `GoukakuWidget`（ウィジェット・Live Activity・コントロール）

### 7.5 時刻改ざん検知

`ClockAnchor`（壁時計＋単調時計＋起動セッション ID）を起動ごとに記録し、同一起動内で壁時計が単調時計からずれたら検知（許容 120 秒）。再起動を挟むと判定しない。判定の保護に使う。

## 8. コミット（習慣）と達成

### 8.1 コミット（HabitSnapshot）

- `title` / `minimumTitle`（最小版。調子の悪い日の小さな目標。無しも可）
- `weekdays`（1=日〜7=土）、`isRequired`（必須なら未達成でロック継続）
- `method`（確認方法）、`targetMinutes`（タイマー/使用時間のとき）
- `activeFrom` / `activeUntil`（有効期間。削除したコミットも **14 日**は残して過去判定に使う）

### 8.2 確認方法（VerificationMethod）と厳しさ

| 方法 | 厳しさ |
|---|---|
| 自己申告 selfReport（一言メモ必須） | 0 |
| 写真 photo / タイマー timer / 使用時間 appUsage / ヘルス health | 1 |
| 場所タイマー placeTimer | 2 |
| 執行役 referee | 3 |

厳しさを上げる変更＝「厳しくする変更」。同段階の変更は「緩める変更」として扱う（§9）。

### 8.3 達成（Achievement）

- `kind`: full（本来の目標）/ minimum（最小版）
- `status`: confirmed（確定）/ pendingReview（事後承認待ち：提出時に解除、却下で未達成に戻る）/ awaitingApproval（同期承認待ち：承認まで解除しない）/ rejected / undone
  - 解除・ストリークに数えるのは confirmed と pendingReview
- `source`: app / monitor（使用時間の自動判定）
- `grantsMinutes`: 稼働型で生む解除枠
- 押し間違いの取り消しは **5 分以内**（取り消すと判定し直し、必要ならロックが戻る）

### 8.4 サイクルの結果（CycleOutcome）

`notStarted`（開始前）/ `rest`（休養日）/ `noCommit`（必須なし）/ `achieved` / `minimum` / `pendingReview` / `paused` / `inProgress` / `missed`。

- ストリーク（連続達成）: achieved/minimum/pendingReview で加算。休養・予定なし・進行中は数えず途切れさせない。未達成・一時停止・開始前で止まる
- 通算達成: achieved/minimum/pendingReview の総数（途切れても減らない）

## 9. 設定変更のルール（ChangePolicy）

「今日の条件は途中で甘くしない」が芯。

- **厳しくする変更**: 原則**即時**。ただし コミット追加・曜日追加・モード変更 は**翌サイクルから**（今日の条件を途中で変えない）
- **緩める変更**: 執行役がいれば**承認**、いなければ**翌サイクルから**。ただし今ロック中（今日が未達成）は緩められない（`lockedNow`）
- **日付切替の変更**: 記録の意味が変わるため、**一時停止中にだけ**可能（`requiresPause`）
- **一時停止中**: ロックが無いので自由に直せる（執行役には再開時に通知）
- 休養日の追加: 週の上限内 & 翌サイクル以降のみ。最小版も週の上限あり

---

## 10. 非常口：緊急解除 / 一時停止 / やめる

### 10.1 緊急解除（EmergencyWindow）

- 申請 → **15 分待機** → **120 分**解除。この数値は安全の床で**変更不可**
- 待機中・解除中は重ねて申請できない。待機中に達成すると待機は取り消し（回数に数えない）

### 10.2 一時停止（PausePeriod）

- ロック全体の非常口。停止中はロックがかからず、設定も自由に直せる
- 判定上は何より優先（`LockEngine` が最優先で `paused` を返す）

### 10.3 やめる（v3: 一文で即解除）

- 文面の芯: 「この仕組みが習慣の補助輪ではなく檻に感じ始めたら、それがやめる合図です。」
- **v3 の挙動**: 「お願いします」「やめさせてください」「参りました」などの**一文で、すぐロックを外す**（＝一時停止を即時に始める。待機なし）
- 厳密な作り（安全最優先）:
  1. **決定的な合言葉判定を端末内で先に行う**（完全一致＋表記ゆれの正規化）。当たれば **LLM を待たず即解除**
  2. それ以外の言い回しは LLM が意図を補助的に判定して解除してよい。**LLM は解除を拒否・保留・条件づけできない**。迷ったら解除側に倒す
  3. 解除後、相棒は**一文だけ**やさしく添えてよい（説教・引き止めはしない）
  4. **最後の保険**: 音声/AI が全く使えなくても解除できる最小操作を常設
  5. 解除は本人のログに残す
- 15 分待機の緊急解除は、摩擦が欲しい人向けの別経路として**残す**。「一文で即解除」とは別物（即解除は一時停止として実装し、EmergencyPolicy の数値は変えない）
- **預け金との関係**: やめるのは常に自由。預け金は自己コミット（本人の口座）なので、途中でやめても他人は得をしない。その週の明日からの分は返金、今日までは結果しだい

## 11. 相棒 AI（端末内）

### 11.1 モデルと方針

- 端末内 MLX（`gemma4-e2b` / `qwen3.5-4b` / `qwen3.5-2b` / `lfm2.5-1.2b-jp`、すべて 4bit）＋ Apple FoundationModels
- **無検閲**（v2.1 で制限文・禁止を撤去。内容フィルタ・ガードレールを足さない）
- 役割: 伴走・提案・下書き。**採点しない・合否を決めない・解除を止めない**
- 口調/人格: 「話しかけてくるのはこの人、あなたは相棒」。小さいモデルが相手になりきらないよう前提を明示
- モデルごとに温度/topP・繰り返し対策（repetitionPenalty、RepetitionGuard）を設定

### 11.2 v3 の 4 機能（すべて端末内・採点しない）

1. **コミットの下書き**: ぼんやりした目標 → 毎日の具体コミット案を複数提案。本人が選び・直して登録
2. **ふり返りの手紙**: その週の結果（うまくいった/難しかった/次の工夫）を AI が下書き → 本人が直して保存
3. **緊急解除の対話**: 解除の前に一度だけ短く話す（「いま何に引っぱられてる?」「5 分でできる代わりは?」）。**止めはしない**。話した後は必ず解除できる
4. **体験の提案**: 進み具合に合わせて現実の体験・ごほうびを勧める（義務ではなく誘い）。体験タブと連動

### 11.3 会話の実行（AI 前提 UX の中身）

- 意図分類＋スロット抽出（check_in / add_commit / edit_schedule / start_deposit / set_amount / reflect / pause / quit / chat …）
- 実行前に短い確認（押し間違いの 5 分取り消しは維持）。**quit/pause は確認なしで即実行**
- 失敗時（モデル未 DL・生成失敗）は、会話なしでも操作できるフォールバックへ静かに落とす

## 12. 預け金（自己コミット・任意）

使うかは自由。使わなければサーバーにもつながない。

### 12.1 しくみ

- カードで **7 日分**を先に預け（1 日 **100〜3,000 円**から選ぶ。サーバー設定で可変）、明日の日付切替から 7 日間、その日の結果で返すかが決まる
- 返金する結果: achieved / minimum / rest / noCommit / notStarted
- **返さない**: missed / paused、そして **pendingReview**（却下で未達成に戻るため、達成が確定するまで返さない）
- 返金を頼むタイミング: 達成はチェックインの取り消し時間（**5 分**）が過ぎたら、休養日・予定なしは日付が変わったら。週が終わってから **7 日**は遅れた知らせも受付、過ぎたら戻らない額が確定
- 戻らなかったお金は**本人の Stripe 口座**（自分で立てたなら自分の口座）へ

### 12.2 自動継続（任意・はじめオン）

- 週が終わると同じカードで次の 7 日分を預ける（サーバーが 15 分ごとに見回る）
- **その週に一度でもアプリを開いた（seen）ときだけ**自動継続する（iPhone 紛失・アプリ削除・放置で預け続けないように。裏の自動更新は数えない）
- 継続の直前に Stripe から状態を読み直す（検索の遅れで止めた人に請求しない）。見回りが半日以上遅れたら過ぎた日を預け金にしない（late）。本人確認（3D セキュア）・カード不通・カード外れは印をつけてアプリで預け直し。失敗後に「続ける」を入れ直したら新しい鍵でやり直す

### 12.3 やめる

- 明日からの分を返金し、自動継続も止める。今日までは結果しだい
- 返金より先に自動継続を止めるので、返金が失敗しても次の週は預けない（返金は同じ画面からもう一度頼める）。やめた週から「続ける」には戻せない

### 12.4 サーバー（Cloudflare Workers・server/）

- 台帳を持たない。Stripe の PaymentIntent（預け）と Refund（返し）そのものが記録
- サーバーが確かめること: 同じ日は二度返さない / 預けた額を超えない / 始まっていない日は返さない / 他人の預け金に触れない
- 端末の合言葉は「Stripe の客 id ＋ HMAC 署名」。台帳不要。合言葉は **iCloud キーチェーン**に保存（iPhone を替えても引き継ぐ）
- **本番キー（pk_live）では招待コード必須**（URL を知った他人が勝手に支払いを作れないように）。GitHub では Secrets に置き、Workers にも secret として入れる
- カード番号はアプリの Stripe 画面から Stripe に直接渡り、アプリにもサーバーにも残らない

### 12.5 窓口

| | |
|---|---|
| `GET /v1/config` | 公開鍵・額の範囲など |
| `POST /v1/register` | 端末登録 → 合言葉 |
| `GET /v1/state` | 最近の週の様子 |
| `POST /v1/deposits` | 7 日分の支払いを作る |
| `POST /v1/deposits/:id/days/:day` | その日の結果（返す結果なら返金） |
| `POST /v1/deposits/:id/renew` | 自動継続の切替 |
| `POST /v1/deposits/:id/cancel` | やめる |
| `POST /v1/deposits/:id/seen` | その週に開いた印＋次の週の日の始まり |
| Cron（15 分ごと） | 週が終わった預け金を次の週へ |

### 12.6 手数料・法務

- Stripe の決済手数料は口座の持ち主負担（返金でも戻らない）。自分だけで使うなら手数料分が自己負担
- **自己コミット（本人の口座に戻る/残る）を越えない。** 他人への送金・賞金プール・紹介報酬などはしない（資金移動業・景表法・賭博・特商法・消費者契約法の対象になり得る）。必要になったら実装前に専門家へ

## 13. データとプライバシー

- コミット・記録・会話・写真は端末内（SwiftData / App Group）に留まる
- 外に出るのは、預け金を使うときの「日付とその日の結果（達成・休養日など）」だけ。一言・コミット名・写真は送らない
- 合言葉は iCloud キーチェーン。設定 › 預け金の「つながりを外す」で消える（外す前に自動継続を止める）

---

## 14. 配布（v3: 一つの IPA）

- GitHub Releases は 1 ファイル **2GiB** 上限。超えるモデルは同梱しない方針にする
- **同梱（単体 IPA）**: `qwen3.5-2b`（約 1.0GB）/ `lfm2.5-1.2b-jp`（約 0.6GB）、加えて AI なしの Release（約 21MB）・Debug（約 33MB）
- **アプリ内 DL / ファイル取り込み**: `gemma4-e2b`（約 2.6GB）/ `qwen3.5-4b`（約 2.4GB）。`models.json` の `ipa` を false にして CI の同梱対象から外す。量子化は下げない（品質最大のまま）
- CI の **part-aa/part-ab 分割は撤去**。Releases に `*.part-*` を作らない
- 実機に入れるには有料 Apple Developer の証明書で署名し直す（アドホック署名は必要なエンタイトルメントを残すため）
